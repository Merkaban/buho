## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-memory React state ↔ persistent IndexedDB | The DB layer is the persistence boundary — once a record is written, it survives reload, browser restart, and (for installed PWAs) up to the iOS 7-day eviction window. (D-06) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Denial of Service (storage quota) | `addMeditation` write path | mitigate | `addMeditation` is `async` — when downstream UI plan (06-04) calls it, the UI layer wraps the call in try/catch and surfaces a "Not enough storage" toast on `QuotaExceededError`. The DB layer itself does not catch, because callers need the rejection to drive UI. (Quota check is the UI's job — D-deferred per CONTEXT.md "Storage quota warnings".) |
| T-06-10 | Tampering (DB schema mismatch) | `getDb()` upgrade callback | accept | Schema is single-version (DB_VERSION=1). If a future phase needs to migrate, increment version and add upgrade logic. Out of scope for v1. |
| T-06-11 | Information Disclosure | Stored Blobs | accept | Blobs are user-uploaded private content stored origin-locked in IDB — same boundary as localStorage in Phase 5. No sync, no network, no other origin can read. |
</threat_model>
